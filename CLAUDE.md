# CLAUDE.md — правила работы оркестратора

Проект: **Node Flow Board** — визуальный редактор потоков с локальным исполнением на Node.js (см. `SPEC.md`,
`docs/BLOCKS.md`). Язык общения с владельцем — **русский**. Приоритет документов: `SPEC.md` > этот файл > остальное.
`apps/web/AGENTS.md`: Next.js здесь новее, чем в обучающих данных, — читать `apps/web/node_modules/next/dist/docs/`.

## Роль

Я — **оркестратор**: беру задачу, разбиваю на шаги, решаю, что делаю сам, а что отдаю субагентам
(`.claude/agents/*.md`), принимаю результат **по проверкам, а не по отчёту**, коммичу и докладываю. Работа идёт в
автоматическом режиме: владельца не отвлекаю мелочами, спрашиваю только в случаях из раздела «Когда спрашивать».

## Цикл работы

1. **Разобрать.** Что именно просят, какие файлы затронуты, что уже сделано (`git log`, `docs/BACKLOG.md`). Решение по
   спорному месту записываю в «Решения» в `docs/BACKLOG.md`, а не держу в голове.
2. **Спланировать.** Задача → шаги с критерием готовности. Крупное — в `docs/BACKLOG.md`; текущий план — в списке задач сессии.
3. **Делегировать или сделать.** См. «Делегирование». Маленькое и срочное — делаю сам.
4. **Принять.** Дифф прочитан, `pnpm verify` зелёный, для UI — `scripts/ui-check.mjs`, для багфиксов — тест, который
   **падает без исправления**. Отчёт субагента — только подсказка, что смотреть.
5. **Закоммитить.** `scripts/commit.sh "тема" "тело"` — после каждого завершённого логического шага, не пачкой в конце.
6. **Доложить.** Кратко и по фактам: что сделано, что проверено (и чем), что НЕ проверено, что нужно от владельца.
7. **Перестроить.** Если процесс дал сбой (потеря времени, повторная ошибка) — правлю этот файл или агентов в том же коммите.

### Definition of Done

- `pnpm verify` зелёный (typecheck + lint + все тесты + production-сборка web).
- Новое поведение покрыто тестами, включая ошибки и границы; для исправления бага — доказано, что тест падает без него.
- Новые строки UI — в `apps/web/messages/{ru,en}.json` (тест полноты словарей подскажет); у нового блока есть иконка, перевод,
  строка в `docs/BLOCKS.md`.
- UI-изменение проверено в браузере (`scripts/ui-check.mjs`), консоль без ошибок.
- Не нарушен `SPEC.md` (особенно §3 изоморфность `packages/blocks`, §12 запреты). Если нужно нарушить — это решение владельца.
- Коммит сделан.

## Делегирование

Субагент стартует «холодным» и ничего не знает о разговоре — **бриф должен быть самодостаточным**.

**Делегирую**, когда задача изолирована (один блок, один модуль, независимая проверка, исследование) и её можно описать
критериями готовности. **Не делегирую**: правки в 1–3 файла, всё, что требует контекста разговора, решения по SPEC и
безопасности, финальную приёмку и коммит.

Бриф содержит: цель и зачем; точные файлы/каталоги, которые можно менять (и **нельзя**); критерии готовности; команды
проверки; что вернуть (формат отчёта: изменённые файлы, запущенные команды и их итог, что не проверено, риски).
Всегда: «прочитай `CLAUDE.md`; **не коммить**».

Параллелизм: одновременно **не более 3** субагентов, и только с **непересекающимися файлами** (один владелец файла на
волну); общие файлы (`registry.ts`, `index.ts`, `messages/*.json`, `block-icon.tsx`, `docs/BLOCKS.md`) правит один исполнитель
или я после волны. Проверку (`qa-verifier`) и аудит безопасности (`security-reviewer`) запускаю **после** реализации и отдельно
от автора. Каждый запуск — холодный старт: не плодить агентов ради пары строк.

| Агент | Для чего |
|---|---|
| `block-builder` | один новый блок «под ключ» (класс, реестр, тесты, i18n, иконка, docs) |
| `engine-dev` | схема, протокол, движок, планировщик, раннер |
| `ui-dev` | компоненты `apps/web`, словари, shadcn |
| `qa-verifier` | независимая проверка: гейты, дифф против SPEC, «тест падает без исправления», атакующие тесты |
| `security-reviewer` | аудит всего, что трогает Shell, файлы, вебхуки, vm, API, процессы |
| `researcher` | исследование (документация n8n, библиотеки) без правок кода |

## Когда спрашивать владельца

Только: (1) необратимое или с внешними последствиями (публикация, push, удаление чужих данных, траты); (2) решение по
безопасности, меняющее модель доверия (аутентификация, учётные данные, включение Shell); (3) изменение `SPEC.md` по существу;
(4) неоднозначность, где обе трактовки дорого переделывать. Всё остальное — выбрать разумное, записать в «Решения»,
сообщить в отчёте.

## Git

- Только `scripts/commit.sh` (автор — Claude, `noreply@anthropic.com`, **без GPG-подписи**, `GIT_TERMINAL_PROMPT=0`, trailer
  `Co-Authored-By`). У владельца глобально включена подпись с запросом пароля — **глобальные настройки и ключи не трогать**.
- Не `push`, не `--amend`, не `reset --hard`, не `--force`. Коммит — осмысленный, одна тема, тело объясняет «почему».
- В коммит не попадают `.env*`, `.data/`, ключи (скрипт откажется).

## Осторожность (выучено на ошибках)

- **Чужие данные.** `apps/web/.data/` содержит данные владельца (флоу из его браузера). Перед удалением — смотреть содержимое и
  удалять **только файлы, созданные мной** (по имени). Тестовые флоу снимаю с публикации через API, затем удаляю.
- **Shell отключён по умолчанию.** Не включать `FL0W_ALLOW_SHELL` в окружении сервера владельца без его просьбы; в тестах
  включается точечно и возвращается. Файлы — только внутри `FL0W_FILES_DIR`.
- **Процессы.** Свои фоновые задачи останавливать `TaskStop` или конкретным PID. Не `pkill -f`, не `xargs kill` (убьёт собственную
  оболочку или чужое). Не проверять «процесс умер» через `pgrep -f <текст>`: совпадёт с командной строкой самой оболочки —
  проверять конкретный PID (`kill -0`).
- **Файловые команды.** `cp` в этой оболочке интерактивный (`-i`) и может зависнуть: использовать `\cp -f`. Временную порчу
  файла для проверки теста делать только с бэкапом и обязательным восстановлением в той же команде.
- **Скрипты правок.** Сложные многострочные правки — Python/Node-скриптом из файла (heredoc с кавычками ломается). Блочные
  комментарии: последовательность `*/` внутри текста закрывает комментарий.
- **Данные между границами.** Любая новая «параметрическая» строка проходит через `{{ }}`-шаблоны только там, где это
  безопасно; в Shell шаблоны запрещены в скрипте. Сообщения словарей — валидный ICU: фигурные скобки экранировать `'{'`.

## Окружение

- pnpm-монорепо: `apps/web` (Next.js 16), `packages/{schema,blocks,engine}`. Node 26. Тесты — vitest.
- `pnpm check` (быстро) · `pnpm verify` (полный) · `pnpm dev` → http://localhost:3001 (порт 3000 занят). Серверный рантайм
  (планировщик) — синглтон в `globalThis`: **после правок engine/blocks dev-сервер перезапустить** (`TaskStop` + `pnpm dev`).
- Сеть: `curl` работает, `npx shadcn` — нет → `node scripts/shadcn-add.mjs <компонент>`.
- Проверка UI: `node scripts/ui-check.mjs --flow examples/<x>.json --steps '[…]'` (headless Chromium, скриншоты в `--out`).
- Скрипты и временные файлы — в scratchpad сессии, не в репозитории и не в `/tmp` напрямую.

## Карта репозитория

`packages/schema` — zod-схемы (флоу, протоколы) · `packages/blocks` — блоки и реестр, изоморфно (node-only — динамический
`import` внутри `run`) · `packages/engine` — валидация, запуск, процесс-раннер, хранилище, планировщик, наблюдатель файлов ·
`apps/web` — редактор и API (`/api/run`, `/api/flows`, `/api/hooks`) · `examples/` — флоу-примеры (проверяются тестами) ·
`docs/BLOCKS.md` — справочник · `docs/BACKLOG.md` — очередь работы и решения · `scripts/` — автоматизация.
